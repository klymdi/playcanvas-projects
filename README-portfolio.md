# Як додати нову гру на сайт-портфоліо

Сторінка `games.html` сама сканує всі папки в репозиторії, шукає в них
`index.html`, і показує їх як картки. Нічого в самому HTML міняти не треба.

## Кроки для нової гри

1. Розпакуй білд у нову папку в корені репозиторію (як і раніше), наприклад:
   ```
   my-new-game/
   ├── index.html
   ├── ...
   ```

2. Додай туди файл `meta.json` (скопіюй `meta.example.json` і зміни під себе):
   ```json
   {
     "title": "Назва гри",
     "description": "Короткий опис на 1-2 речення.",
     "logo": "logo.png",
     "tags": ["PlayCanvas", "Mobile"]
   }
   ```
   Якщо лого ще нема — просто прибери рядок `"logo"` або залиш його, картка
   покаже заглушку з ініціалами, поки файл не з'явиться.

3. (Опційно) додай лого/скріншот в ту саму папку, наприклад `logo.png`
   (шлях у `meta.json` має збігатись з назвою файлу).

4. Закомить і запуш:
   ```bash
   git add my-new-game/
   git commit -m "Add my-new-game"
   git push
   ```

5. Почекай 1-2 хв на редеплой GitHub Pages — гра сама з'явиться на
   `games.html`, без правок коду сторінки.

## Якщо гра НЕ має з'являтись на сторінці (не гра, а службова папка)

Додай назву папки в список `IGNORE_DIRS` всередині `games.html`
(на початку `<script>`).

## Нюанс з лімітом GitHub API

Сторінка тягне список файлів через публічний GitHub API
(`api.github.com`), у якого є ліміт ~60 запитів/годину без авторизації
на IP відвідувача. Для особистого портфоліо з невеликою кількістю
відвідувачів це, як правило, не проблема. Якщо колись стане проблемою —
можна замінити на статичний `games.json` у корені репозиторію, який
оновлюється при кожному пуші через GitHub Actions.
